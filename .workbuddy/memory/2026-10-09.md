## 修复：Agent 对话框向上滚看历史被心跳同步拽回底部

现象：在对话框内向上滚动看历史，1-2 秒后自动跳回最底部（用户怀疑是 heartbeat/sync）。

根因：`ApiWorkspace.tsx` 的滚动 `useEffect` **无条件**执行 `scroll.scrollTop = scroll.scrollHeight`，
而它的依赖里含 `prdAgentProgress.detail/stage/activitySteps`、`activeRuntime.current_summary`、
`workflowProgress`、`busy`、`state.phase` 等**轮询/SSE 心跳式更新**的字段——后台同步每 ~1s 变一次
→ effect 反复触发 → 把正在看历史的用户拽回底部。与「有没有新消息」无关。

修复（只在前端；HMR 刷新即可，无需重启后端三、不涉及后端）：
- 新增 `frontend/aios-main/src/api/chatScroll.ts`：纯函数 `isChatNearBottom(metrics, threshold=48)`
  （`scrollHeight - scrollTop - clientHeight < threshold`）。
- `ApiWorkspace.tsx`：
  - 新增 `chatPinnedRef`（默认 true），滚动容器 `.ff-chat-scroll` 挂 `onScroll={handleChatScroll}`，
    用 `isChatNearBottom(event.currentTarget)` 实时更新 pin 状态；
  - 滚动 effect 加守卫：`if (scroll && chatPinnedRef.current)` —— **只有贴着底部才自动滚**；
  - 用户自己发送消息时（`submitChat`）置 `chatPinnedRef.current = true`（自己的新消息要看到）；
  - `activeSessionId` 变化时重置为 true（切会话/首开显示最新）。

守护测试：`src/api/chatScroll.test.ts`（5 例）——纯函数边界（<48 贴底、≥48 脱离）+ 两条源码级断言
（effect 必须带 `chatPinnedRef.current` 守卫、容器必须挂 `onScroll={handleChatScroll}` 且用纯函数计算）。
- 探针：临时把守卫改回 `if (scroll)` → 源码级用例变红（1 failed/4 passed），已恢复。
- `tsc --noEmit` exit 0。

## 排查其它「心跳导致乱跳」并收尾（滚动守卫通用化）

用户追问：是否还有别的心跳信号导致胡乱跳转。做了全前端滚动/聚焦/切页审计。

**修的第 2 处（真实应用内）：PRD 阅读区流式跟随**
`RenderedPrdDocument.tsx` 的 effect `scrollIntoView(streamingBlockId ?? selectedBlockId)`——
生成时 Agent **逐块**流式写入，`streamingBlockId` 每换一块就触发一次，用户在看别处时被反复拽走。
拆成两个 effect：
- `selectedBlockId` 变化 → 始终滚动（显式导航：点目录/点正文块）；
- `streamingBlockId` 变化 → **仅当读者仍贴着底部才跟随**（`readPinnedRef`）。
容器 `.prd-rendered-document`（CSS 确认 `overflow:auto` 就是滚动容器）挂 `onScroll={handleReadScroll}`。

**通用化**：`chatScroll.ts` → 重命名抽为 `src/api/scrollPin.ts`
（`isNearBottom(metrics, threshold=48)` + `SCROLL_PIN_THRESHOLD_PX`），聊天与阅读区共用；删除旧文件与其旧测试。

**审计结论（其余均无问题，不改）**：
- `ProjectMindMap` 居中：有 `centeredRequestRef === centerRequest` 守卫，只在用户动作时居中，非轮询。
- `BlockTree` 目录自动滚动：依赖 `selected`（用户点选），非心跳。
- `PRDEditor` 关注批注 `scrollIntoView`：`focusedCommentId` 用户驱动。
- `FullDocumentView` / `TopLevelGraph`：无滚动代码（后者有"保留平移缩放"测试）。
- `setWorkbenchOpen`/`setDocumentMode`/`setActiveTab`：全部用户或命令驱动；`useEffect` 无轮询自动切页/自动展开/抢焦点。
- `components/AgentChat.tsx` 有同样的无条件 `scrollToBottom`，但**只被 MockApp（演示壳）引用**，不在真实应用里，未改。

守护测试：`src/api/scrollPin.test.ts`（6 例：阈值边界 + ApiWorkspace 聊天守卫接线 + RenderedPrdDocument 阅读区守卫接线）。
