# Create PRD

Build the PRD from authenticated source material. Never turn an assumption into a
confirmed fact or approval.

Cover the following product dimensions wherever they belong in the supplied Block
structure:

1. concise summary and problem;
2. affected users, roles and scenarios;
3. background and why the work matters now;
4. measurable objectives and success indicators;
5. scope, exclusions and release boundaries;
6. value proposition and named tradeoffs;
7. solution behavior, flows, objects, permissions and failure handling;
8. assumptions, open questions, risks and release sequence.

Keep the language direct and accessible. Requirements must be observable and must
connect to the stated user problem. Preserve the host application's Block IDs,
version contract and DOCX publishing rules; do not create a separate Markdown file.
