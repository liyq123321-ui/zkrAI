# 原文解释与工程补充

以下规则解决原文不完备处，均显式记录，不能冒称原文已有这些细节。

| 问题 | 采用的解释与实现 |
| --- | --- |
| 无立项阶段，但阶段准入写“立项完成” | 保留原文准入文本；把立项视为已有背景输入，不新增审批阶段，不虚构立项记录。 |
| 模式二“1～4不满足” | 指模式一未达到至少 3 个是的阈值，不是要求四题全为否。 |
| 模式三与其它模式同时达标 | 原文未定义优先级；除已明确的严格串行硬约束外，多候选停止选择并澄清。不能默选敏捷或混拼阶段。 |
| 业务明确要求完全串行（q4） | 属于硬约束；仅纯线性瀑布可满足。仍需达到模式一阈值；不达阈值则澄清，不强行补分。 |
| 信息缺失 | 支持 yes/no/unknown。穷举未知项所有取值；只有所有情况都选同一个模型才可继续，不影响选型的未知项无需多问。 |
| 原文未给出精确预估数字 | 引用 PRD 中已确认事实。没有证据必须 unknown；结构检查只验证引用存在，Reviewer 检查引用含义和假设是否误作事实。 |
| 瀑布“缺陷必须源头回退”与测试 Bug 例外 | 具体例外优先：测试内代码 Bug 原地修复回归；需求/设计问题溯源回退并重评。 |
| 测试“缺陷清零”与明确准出标准 | 必须满足原文明确的高危/严重缺陷清零；其余缺陷也须闭环记录，不用口号替代实际验收阈值。 |
| 迭代规划需上一轮验收，但又允许上一轮验证时开始下一轮规划 | 区分预规划和正式承诺：上一轮开发准出后可开始下一轮需求拆解；下一轮规划准出要等上一轮验证门禁。第一轮只需全局启动通过。 |
| 原文称高度并行，但没有并发上限 | 当前 DAG 支持保守的双迭代流水；第三轮预规划等待前前轮发布。属于实现限制，不宣称原文要求两轮上限。 |
| 阶段工作与全项目预先规划 | 允许预先生成完整路线与任务说明；阶段工作是否启动由执行依赖约束。生成下游任务规格不代表下游正式工作已开始。 |
| 未明确覆盖率及稳定观察周期 | 不发明百分比或天数；在计划中安排责任人确认可验阈值，后续门禁按项目约定验证。 |
| 排期区间相加不等于 100% | 保留建议值，不以其总和作硬校验；计划说明实际时长、重叠与运维交接，Reviewer 判断可行性。 |
| 长期运维没有终点 | 阶段仍保留；有限交接任务配持续服务约定。持续运维不是每轮迭代的最后一道阻塞门禁。 |
| 已有已批准 PRD | 复用已有证据、检查版本与追溯，不要求为已完成且有证据的工作伪造重复实施；计划中可建立核验/交接任务。 |
| 批准范围明确不含上线等生命周期工作 | 不擅自新增实际部署；Reviewer 提出范围决策。不能为了通过结构校验暗中删除阶段或宣称部署已做。 |
| 阶段数量与迭代编号 | 纯瀑布 6、重叠瀑布 5；迭代只有 4 个循环阶段编号 1～4，全局/持续阶段标记为 0，不当成第 5/6 个迭代阶段。 |
| 可机器检查与需实际审核 | 阶段/覆盖/依赖可强制；引用含义、真实签字、业务质量依赖实际审核。保存计划不改变审批事实。 |

规则修改后应更新本文件、JSON Schema 和示例，并运行规则与服务集成测试。
当前模型/阶段顺序是受支持的解释器语义；需要新增第四种模型或更复杂并行机制时，
必须同步扩展解释器及反例测试，不能只添加无人执行的 YAML 字段。
