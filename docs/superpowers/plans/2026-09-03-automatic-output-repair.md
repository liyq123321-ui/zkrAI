# PRD 与子任务结构缺漏自动修复

用户要求：遇到未定义需求引用等异常时，自动补齐相关缺漏。

## 原因与处理范围

真实会话 `767932e2-b720-4065-98e3-099119f29880` 的第一版 PRD 在验收条件中引用了未定义的 `deliverable-001`。该引用沿用到 v3，再传入拆分结果；旧 PRD 规则未检查未知需求引用，直到拆分才报错。

在 Codex 结构化输出返回服务之前运行与持久化边界共享的规则。适用于 PRD 生成、基于审核意见改写 PRD、拆分子任务。修复范围包括未知需求引用、重复需求编号、缺少验收覆盖、不可验证的验收条件、缺少章节、资料引用、任务父子关系、依赖与产物。补充任务验收对所有正式 FR/NFR 的覆盖检查。

## 执行与边界

- 一次初始输出、最多两次修复；JSON/schema 错误和结构一致性错误共用三次调用预算。
- 每轮把上一次完整输出与当前诊断作为非控制数据交回 Agent，要求修复关联缺漏并返回完整结果，保留有效内容。
- 生成及改写的 PRD 可以依据已有证据补全需求定义与关联验收；随后仍按原流程创建版本并审核。
- 已确认 PRD 保持内容、版本和哈希不变。拆分时从正式需求定义取合法编号，旧验收中的错误编号应关联到已有匹配需求；没有依据时保留待决问题。
- 人工决策、风险接受和职责授权不以结构修复为由自动消除；语义 Reviewer 与最终事务内校验继续生效。
- 修复耗尽或语义审核拒绝时保持原流程状态，不保存半套子任务。命令仍按原幂等机制重试。
- 服务保留最终 Agent 调用结果；结构化日志记录各轮失败的契约类型、次数与错误代码，不记录完整输出或凭据。

## 验证

- 先复现旧行为：未知编号、多项 PRD 缺漏、任务产物/依赖/覆盖/引用错误都不能自动恢复。
- 新增真实 gateway/runner 测试，只替换外部 CLI 返回；覆盖多项修复、改写评论保留、历史 PRD 不变、共享重试上限、人工问题保留。
- 集成验证生成一版审核中 PRD、修复后原子落库、命令重放不重复调用 Agent、修复耗尽与语义拒绝不写入任务。
- 新进程测试确保服务先于 gateway 导入时不会循环依赖。
- 真实失败结果只读回放：将 `deliverable-001` 关联到已有 `FR-009` 并去重后，所有新结构校验通过；未修改原始记录。
- 代码复核补充：审核评论回复的遗漏、重复和未知编号纳入同一修复循环；复用服务端冻结评论覆盖规则。生成集成测试使用真实 CommandService 入口，并验证 Reviewer 调用失败时不写入版本、不递增状态。
- 全部后端测试：427 项通过（两个既有依赖弃用提示）。
