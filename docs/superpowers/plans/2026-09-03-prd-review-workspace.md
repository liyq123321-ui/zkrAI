# PRD 阅读与项目进度修复

目标：修复已部署工作台的 PRD 打不开问题，默认并排展示完整 Markdown 正文与真实 Diff，让审计详情可以展开，并解释项目进度与下一步。

## 已确认原因

1. Gitea 1.27.3 的 PR files API 只返回文件统计，不含 patch；后端错误地要求该字段，导致可批注行返回 422。
2. 前端以 Promise.all 加载正文、批注、历史；批注失败会隐藏成功读取的正文，且卡片仅在页面下方插入内容。
3. 审计列表未实现详情交互。Session 区域直接显示内部英文枚举；只有 v1 时仍展示无法选择的历史版本操作。

## 实施与验证

- [x] 为缺失 patch 的真实 Gitea 响应编写失败回归测试；从官方 pulls/{index}.diff 获取并严格提取目标文件的 diff，保留源行号校验与拒绝无效批注的行为。覆盖多文件隔离、不可批注行、实际评论写入参数。
- [x] 为 PRD 批注接口失败时仍可读正文编写组件回归测试；用可关闭的对话框打开任务详情，将正文和批注服务的加载结果分开，批注数据不完整时不允许审批或发布。
- [x] 审计事件支持展开已返回的安全字段，并关联对应 PRD 内容和审核结论；不读取或展示模型原始推理或受限诊断。修正无时区 UTC 时间在浏览器中的展示。
- [x] 将 Session 区域改为中文项目进度和下一步指引；显示审核待解决问题，把标识和历史恢复作为次要信息；无历史版本时不显示不可用操作。
- [x] 运行针对性回归测试、完整已有测试、类型检查和生产构建；重启本地后端并更新前端，在用户项目上只读验证正文、批注行、审计与状态，不替用户批准或重新生成 PRD。
- [x] 独立代码审查，记录部署结果，提醒用户保存 Git。
