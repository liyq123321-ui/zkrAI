# 依据已确认 PRD 自动修订拆分

用户确认：语义审核指出子任务与现有 PRD 不一致时，依据该 PRD 自动修订。

- 保留已确认 PRD 的版本、正文、哈希和批准状态。
- 每次输出先结构校验，再独立语义审核。可修订的拒绝意见交回 PM，附原拆分、完整审核反馈和来源审核调用 ID，仅返回需要修改的已有条目。服务按键合并后对完整方案校验、复审，保留所有未修改条目；禁止新建、删除、重命名或重复替换键。
- 优先继续同项目、同 PRD 版本、哈希和内容绑定的最新拒绝记录，避免重新生成整套任务。无修订轮次的历史记录视为初始结果。
- 初始拆分加最多两轮语义修订；同命令恢复时沿用已耗轮次，不重置预算。新命令可开始新的有限修订尝试。
- NEED_INFO、明确需要新人工决策或风险接受的问题保留具体原因。审核持续拒绝、Agent 调用失败、结构校验失败都不写入部分任务。
- Reviewer 同时阅读每条任务的 scope/exclusions/constraints/extension_points，区分批准范围内的未来扩展与当前扩大范围，避免从孤立短语推导越界授权。
- 每轮独立 AgentCall 留存输入、输出；拒绝记录和是否继续修订进入审计。最终仅标记实际采用的 PM 与通过审核的 Reviewer 调用成功；历史调用保留。
- 最终命令事务再次核对当前 PRD 的版本、批准状态、内容、哈希和输入引用，随后原子创建所有任务与 Agent Spec。

验证覆盖：首次拒绝后修订成功、命令重放不重复创建、持续拒绝到达上限、旧拒绝记录续修、过期 PRD 反馈不复用、修订期间 PRD 变化中止、同命令中断恢复不重置预算，以及最终命令入口完整快照变化时回滚。

最终验证：441 项后端测试通过，代码复核发现的预算恢复与提交快照两处问题均已修复并复查。另有 A/B/A 交错命令测试，验证别的命令的新审核记录不能遮住原命令已耗尽的预算。局部替换经过真实 Gateway→合并→完整审核→保存的集成测试，并覆盖未知/重复键及错误需求引用和依赖的自动重试。

实际会话验证（2026-09-03）：767932e2-b720-4065-98e3-099119f29880 在全量修订调用 900 秒超时后，切换局部修订并加载新后端。沿用原命令重试，共约 144 秒完成两轮修订/审核，最终 PASS、无 findings；原子保存 3 个里程碑、12 个子任务及 12 个 Agent Spec。状态为 AGENT_SPECS_READY、state_version=19，PRD v3 的正文、哈希及批准状态保持一致。页面刷新后卡片数量正确且旧错误提示清除。
