# Tasks 依赖 DAG 泳道设计

## 目标

在 `DAG Flow Map` 的子任务区域中直接表达任务间的前置依赖。用户应能从左到右阅读执行顺序，并继续通过点击节点打开对应 WorkItem 详情。

## 展示结构

- Root 和 Milestones 区域继续展示现有层级信息。
- Tasks 区改为横向 DAG 画布，并按 Root WorkItem 所属项目分成独立泳道。
- 每条项目泳道使用 Root WorkItem 名称作为标题。
- 子任务依据后端返回的 `graph_depth` 从左到右分层；同一深度的任务纵向排列。
- 每条 `dependency_work_item_ids` 关系绘制为从前置任务指向后继任务的曲线箭头。
- 不同项目之间不绘制连线，避免共享看板中的项目关系混淆。

## 数据和交互

- 前端只读取 `graph_depth` 和 `dependency_work_item_ids`，不推导或修改任务执行规则。
- 如果依赖目标存在于当前项目的 Tasks 集合中，则绘制连线；缺失或跨项目的引用不绘制。
- 任务节点保留标题、ID、责任 Agent、依赖数量和当前点击行为。
- 点击任务节点打开对应 WorkItem 详情页面。
- Tasks 区支持横向和纵向滚动，以容纳较深或较宽的依赖图。

## 组件边界

新增独立的任务 DAG 组件，负责：

1. 按项目聚合 Tasks。
2. 按 `graph_depth` 生成层级列。
3. 注册节点 DOM 引用并计算连线路径。
4. 在尺寸变化时重新测量连线。

`ApiWorkspace` 负责提供 WorkItem、项目映射和节点点击回调。组件不调用后端，也不持有任务状态。

## 可访问性和异常情况

- DAG 节点使用原生按钮，可通过键盘聚焦和打开。
- SVG 连线标记为装饰内容，不进入读屏顺序。
- 没有子任务的项目显示空状态；没有任何项目子任务时显示统一空状态。
- 无依赖任务位于第一层，即使后端未返回 `graph_depth` 也按深度 0 展示。

## 验证

- 组件测试验证按项目分组、深度列、依赖连线元数据和节点点击。
- 工作区集成测试验证切换到 DAG 标签后能看到任务依赖图。
- 运行 TypeScript 检查、前端完整测试和生产构建。
