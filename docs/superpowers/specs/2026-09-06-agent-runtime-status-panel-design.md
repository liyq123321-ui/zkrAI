# Agent 实时运行状态面板设计

## 目标

在工作台的“审计记录”Tab 顶部增加一个全工作台 Agent 实时运行状态面板，让用户无需展开审计事件即可看到：

- 已启动的 Agent 数量；
- 运行中、已完成和异常的 Agent 数量；
- 每个 Agent 当前或最近一次执行的状态、阶段、摘要和时间信息；
- Agent 所属项目。

本功能只提供只读运行态观察，不增加启动、停止或重试 Agent 的控制能力。

## 范围与统计口径

面板覆盖当前工作台已经加载的全部项目，并按项目分组显示。

“一个 Agent”对应一个持久化的 `AgentSession`。同一 Agent 发起多次 `AgentCall` 时不重复计数，使用最新一次调用描述其当前状态。只有至少存在一次调用的 Agent 才计入“已启动 Agent”。

状态映射如下：

- `PENDING` 以及其他未完成状态：运行中；
- `RESULT_READY`、`SUCCEEDED`、`COMPLETED`、`NO_CHANGE`：已完成；
- `FAILED`、`AMBIGUOUS`：异常；
- Agent 存在但最新调用已经完成，且后续没有调用：在明细中显示已完成，而不是推断为仍在运行。

顶部指标包含“已启动”“运行中”“已完成”“异常”。各状态数量之和等于已启动 Agent 数量。

## 后端设计

### 只读接口

增加：

```text
GET /sessions/{session_id}/agents/runtime
```

接口只读取当前项目的 `AgentSession` 和 `AgentCall`，不触发 Agent，不改变工作流状态，也不写入审计事件。

返回列表中的每个元素包含：

- `agent_session_id`
- `project_id`
- `role`
- `provider`
- `model`
- `purpose`
- `status`：`running | completed | error`
- `current_operation`
- `current_summary`
- `current_call_id`
- `started_at`
- `completed_at`
- `call_count`

查询服务按 `AgentSession` 聚合调用，选择 `(started_at, id)` 最大的调用作为最新调用，并将数据库内部状态映射为稳定的公开状态。执行摘要复用现有 `AGENT_TRACE` 的 operation 摘要映射，避免审计记录与状态面板出现不同文案。

接口继续遵守现有错误分类和资源归属校验：不存在的 Session 返回当前标准的未找到错误；不返回请求正文、响应正文或诊断错误详情。

### 结构边界

Agent 运行状态使用独立的读取模型，不从审计事件反向推导。审计事件仍负责展示历史证据；运行状态接口负责提供当前快照。公共的 operation 摘要映射抽取为查询服务内的单一实现，供两种读取模型复用。

## 前端设计

### 数据获取

为 Agent 运行状态增加 DTO 和 API 客户端函数。审计 Tab 激活时，对工作台中已加载的所有项目并行请求运行状态接口，并合并为全工作台快照。

刷新规则：

- 切换到审计 Tab 时立即刷新；
- 审计 Tab 保持激活时每 2 秒刷新；
- 离开审计 Tab 或组件卸载时取消请求并停止定时器；
- 项目列表发生变化时，下一次刷新自动使用最新列表；
- 防止较旧请求覆盖较新的快照。

一次刷新部分失败时，保留对应项目上一次成功快照，并在面板内显示非阻塞警告；其他项目的成功结果照常更新。失败不会清空审计记录，也不会复用工作流命令的全页错误状态。

### 面板布局

面板置于审计事件列表上方，包含：

1. 汇总区：已启动、运行中、已完成、异常四个数字；
2. 项目分组区：使用项目标题作为分组标题；
3. Agent 行：展示角色/名称、状态徽标、当前阶段、执行摘要、开始时间、持续时间或完成时间、累计调用次数；
4. 空状态：尚无 Agent 调用时显示“暂无已启动 Agent”；
5. 刷新错误：在面板内显示简短提示，并明确当前展示的是最近一次成功快照。

运行中的持续时间由浏览器根据 `started_at` 计算，并随轮询更新。所有面向用户的阶段和状态名称继续通过展示层映射为中文。

## 数据流

```text
AgentSession + AgentCall
        │
        ▼
QueryService 生成项目运行快照
        │
        ▼
GET /sessions/{id}/agents/runtime
        │
        ▼
审计 Tab 按项目并行轮询
        │
        ▼
全工作台汇总指标 + 项目分组 Agent 明细
```

## 测试策略

### 后端

- 验证同一 Agent 多次调用只返回一行，并选择最新调用；
- 覆盖运行中、已完成、异常状态映射；
- 验证调用次数、角色、模型和时间字段；
- 验证没有调用的 Agent 不计入已启动列表；
- 验证接口只返回公开字段，不泄露请求、响应和错误详情；
- 验证跨项目数据不会进入当前 Session 的结果。

### 前端

- 验证四个汇总指标和按项目分组；
- 验证 Agent 最新执行信息和状态文案；
- 验证审计 Tab 激活时立即请求并按 2 秒刷新；
- 验证离开 Tab 后停止刷新并取消未完成请求；
- 验证部分项目刷新失败时保留旧快照并显示非阻塞警告；
- 验证空状态；
- 保留现有审计记录展开与审核证据测试。

## 非目标

- 不增加 Agent 启停、重试或终止按钮；
- 不引入 WebSocket 或 SSE；
- 不显示 Agent 请求、响应正文、内部错误堆栈或敏感诊断信息；
- 不改变 Agent 调度、并行度或工作流状态机；
- 不持久化前端派生的持续时间和汇总数字。
