# ER 图字段布局容错设计

## 目标

Agent 生成的 ER 图不得因 `tableRow` 的子节点数量或类型不符合规范而阻断整份 PRD。系统仍需确保字段标签在 draw.io 查看器中以横向、可读的形式展示，避免旧问题中的竖排字段。

## 决策

在 Agent 输出边界，先对可解析且通过既有安全/实体/关系校验的 XML 做布局规整，再继续生成 PRD：

- 行自身携带字段文本时，移动文本到新建的 `partialRectangle` 子单元格；
- 每个已有字段单元格都去掉相对 `1×1` 几何，并继承所属行的绝对宽高；
- 若 Agent 将 ER 实体写成 `swimlane`，读取和生成边界都转换为 `table` 容器；实体高度重算为标题行加字段行之和，空布局行不参与渲染；
- 允许空行、多个子字段单元格，或未知的非字段布局子节点；它们不再作为 PRD 生成失败的原因；
- 不可解析/不安全 XML，以及少于两个实体或没有有效关系的图，继续失败。

不重写已经保存的历史 PRD 图。布局修复只发生在新的 Agent 输出写入版本前。

## 验证

单元测试覆盖多子单元格行：校验不会阻断，所有可识别字段单元格都会具有行的绝对宽高且没有 `relative` 属性。现有直接写在行上的字段和 1×1 相对字段测试继续通过。
