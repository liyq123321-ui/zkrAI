# Agent 实时活动流设计

## 目标

将审计记录页顶部的“Agent 实时运行状态”从静态阶段摘要升级为类似 Codex 会话的活动流。运行中的 Agent 能显示当前正在做什么、近期完成了哪些活动，以及每项活动可折叠的详细内容。

## 用户体验

每个运行中 Agent 行展示活动流：

- 当前活动始终可见且带有运行动画；
- 已完成活动按时间倒序显示；
- 每项活动具有简短标题、状态和更新时间；
- 当前活动默认展开，历史活动默认折叠；
- 展开后显示可公开的结构化详情，例如工具类别、目标文件、写入内容摘要和有限的变更片段；
- 完成后的 Agent 收起活动流，仅显示“已完成 N 个活动”，用户可手动展开查看。

运行状态面板继续每两秒刷新；新活动到达时保留已经看过的活动，不因轮询覆盖而闪烁或倒序。

## 数据模型与安全边界

新增持久化的 `AgentActivity` 记录，属于一次 `AgentCall`。它只包含允许展示的字段：

- `id`、`agent_call_id`、`sequence`、`status`、`kind`、`title`、`details`、`created_at`、`completed_at`；
- `details` 是受限的 JSON 结构，只允许工具类别、经过规范化的工作区相对路径、产物摘要和受长度限制的文本片段；
- 不保存或返回提示词、模型隐藏推理、原始命令/参数、完整工具输出、文件全文、环境变量、令牌或错误堆栈。

后端建立单一的活动净化与投影层。Codex JSONL 事件会转换成白名单活动，如“准备任务上下文”“调用工作区工具”“读取文件”“修改文件”“校验结构化结果”。任何无法识别或无法安全净化的事件只记录为通用阶段，不保留原始负载。

活动详情中的路径必须位于配置的工作区内，并转为相对路径；文本片段设置固定长度上限。每个调用只保留最近有限数量的活动，防止无限增长。

## API

扩展 `GET /sessions/{session_id}/agents/runtime` 的每个 Agent 项：

- `activities`：最新活动在前的安全活动列表；
- `activity_count`：该调用持久化的活动总数；
- `last_activity_at`：最近一次活动发生时间。

原有字段及状态映射保持兼容。接口仍按项目隔离，且不泄露 `AgentCall` 的请求、响应、错误字段或原始 JSONL。

## 事件流

```text
Codex JSONL / 服务阶段进度
        │
        ▼
活动净化与分类（白名单）
        │
        ▼
AgentActivity（关联 AgentCall）
        │
        ▼
运行状态快照 API
        │
        ▼
审计页每 2 秒轮询 → 可折叠活动流
```

服务层的高层进度（例如“正在进行一致性审核”“正在写入 WorkItem”）也要写入同一活动流，因此没有 Codex 工具事件的工作仍能提供连续反馈。

## 测试

- 后端验证 JSONL 和服务进度到活动记录的白名单映射；
- 验证路径归一化、长度限制和未知事件降级；
- 验证运行时接口只返回安全字段、按 AgentCall 隔离并以正确顺序返回活动；
- 验证轮询期间活动累积和更新；
- 前端验证运行态自动展开、完成态折叠、详情展开、空活动降级和刷新时不闪烁；
- 验证不渲染被禁止的字段。

## 非目标

- 不显示模型隐藏推理；
- 不显示原始命令、命令参数、完整工具输出或文件正文；
- 不改变 Agent 调度、命令执行、审计事件语义或轮询频率；
- 不引入 WebSocket/SSE。
