# Milestone 子任务监控设计

## 目标

在 Kanban 的 Milestone 卡片中增加紧凑的子任务状态汇总，并在 Milestone 详情页中用卡片和连线展示完成该里程碑所需子任务的执行顺序、依赖关系和实时状态。用户点击任一子任务节点后，应直接进入对应 WorkItem 的详情页面。

## 范围

- 一个 Milestone 的监控范围仅包含 `kind === "TASK"` 且 `parent_id` 等于该 Milestone ID 的 WorkItem。
- 不递归纳入其他层级，也不展示属于其他 Milestone 或其他项目的任务。
- 前端只读取后端返回的 WorkItem、状态和依赖字段，不修改任务状态或依赖关系。
- 本次不调整全局 `DAG Flow Map` 的数据范围和交互。

## Milestone 卡片状态汇总

Milestone 看板卡片新增一行紧凑汇总，位置位于任务目标与负责人/进度区域之间。汇总由当前 Milestone 的直属 TASK 实时计算：

- 始终展示子任务总数，例如“5 个子任务”。
- 存在 `in_progress` 任务时展示进行中数量。
- 存在 `blocked` 或失败态任务时展示受阻数量并使用警示色。
- 所有子任务均完成时展示“全部完成”。
- 没有子任务时展示“暂无子任务”。
- 其他待执行状态不单独占用汇总空间，避免 Milestone 卡片过于拥挤。

汇总只负责监控提示，不增加独立点击行为；点击 Milestone 卡片仍打开 Milestone 详情。

## Milestone 详情布局

Milestone 使用专属详情内容，不再按普通 TASK 的 Agent Spec 详情呈现。详情由以下区域组成：

1. 标题区：Milestone ID、类型、当前状态、标题和目标。
2. 概览区：子任务总数、已完成、进行中、受阻等统计。
3. 子任务执行监控图：展示卡片节点、执行层级和依赖连线。
4. 空状态：Milestone 尚无直属子任务时显示明确提示。

## 子任务执行监控图

### 分层规则

- 仅在当前 Milestone 的任务集合内解析 `dependency_work_item_ids`。
- 没有本集合内前置依赖的任务位于第一层。
- 后继任务位于其最深前置依赖的下一层。
- 同一层任务横向并列，表达可并行执行。
- 不同层自上而下排列，表达依赖驱动的执行顺序。
- 依赖引用指向本 Milestone 之外的任务时不绘制连线，也不将外部任务加入图中。
- 若数据异常形成循环依赖，无法完成拓扑分层的任务集中放入最后一个“依赖异常”层，页面继续可用并给出异常提示。

### 连线规则

- 每一条有效依赖从前置任务卡片底部指向后继任务卡片顶部。
- 使用带箭头的 SVG 曲线路径，线条不参与读屏顺序。
- 无依赖的并列任务之间不连线。
- 容器或节点尺寸变化时重新测量端点，保证弹窗宽度变化后连线仍对齐。

### 任务节点

每张子任务卡片展示：

- 标题和 WorkItem ID；
- 责任 Agent；
- 当前状态；
- 前置依赖数量（存在依赖时）。

状态继续使用现有 WorkItem 映射：待执行、进行中、已完成、受阻/失败，并通过文字、图标和颜色共同表达，不能只依赖颜色。

节点使用原生按钮。鼠标点击、Enter 或空格均调用现有 `setSelectedWorkItemId` 详情切换逻辑，直接打开该子 WorkItem 的详情；弹窗保持打开并滚动到新详情顶部。

## 组件边界与数据流

新增独立的 Milestone 监控组件，职责包括：

- 根据 Milestone ID 从同项目 WorkItem 中筛选直属 TASK；
- 计算卡片汇总统计；
- 在详情中计算拓扑层级并渲染节点与连线；
- 将节点点击以 WorkItem ID 回传给 `ApiWorkspace`。

`ApiWorkspace` 负责：

- 向看板卡片提供对应 Milestone 的统计结果；
- 在选中项为 `MILESTONE` 时渲染 Milestone 专属详情；
- 继续持有和更新 `selectedWorkItemId`。

普通 TASK 继续使用现有 `AgentSpecDetail`，Root 继续使用 PRD 审核详情。全局 `TaskDependencyGraph` 保持现状，避免为两种阅读方向引入大量条件分支。

## 状态与刷新

监控数据来自 `useWorkspaceProjects` 已加载的 WorkItem 集合。资源刷新或任务命令完成后，React 会基于新状态重新计算统计和图形，无需新增轮询或后端接口。

## 可访问性与响应式

- 监控区域使用带 Milestone 名称的可访问标签。
- 节点为可聚焦按钮，状态包含可读文本。
- SVG 连线设置为装饰内容。
- 窄屏下图区域允许横向滚动；同层卡片保持可辨识的最小宽度，不将文字压缩到不可读。
- 空状态和循环依赖异常均使用文本说明。

## 测试与验收

组件测试覆盖：

1. 汇总只统计当前 Milestone 的直属 TASK。
2. 无任务、进行中、受阻和全部完成时的汇总文案。
3. 无依赖任务在同一执行层并列展示。
4. 有依赖任务按自上而下的层级展示并生成对应连线。
5. 外部依赖不生成节点或连线。
6. 循环依赖进入异常层并显示提示。
7. 节点显示任务状态并在点击后回传正确 WorkItem ID。

工作区集成测试覆盖：

1. Milestone Kanban 卡片显示紧凑汇总。
2. 点击 Milestone 打开专属监控详情。
3. 点击监控图中的 TASK 后切换到该 WorkItem 详情。

最终验证运行 TypeScript 检查、前端完整测试和生产构建。
