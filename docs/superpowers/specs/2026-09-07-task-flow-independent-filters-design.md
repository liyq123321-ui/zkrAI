# 任务流转图独立筛选栏设计

## 目标

在 `DAG Flow Map（任务流转图）` Tab 中增加与 Kanban 一致的筛选能力，同时让两个 Tab 各自保存筛选条件。用户在两个视图之间切换时，不会互相覆盖搜索词或筛选选择。

## 范围

任务流转图新增以下四类筛选：

- 搜索：匹配工单 ID、标题、目标、描述或执行者。
- 主任务：多选主任务，并包含所选主任务下的全部 WorkItem。
- 类型：全部类型、项目需求、里程碑或子任务。
- 执行者：全部 Agent 或一个具体执行者。

本次不增加新的后端接口，不修改 WorkItem 数据结构，也不改变节点详情、任务状态或依赖关系。

## 交互设计

任务流转图的筛选栏放在 Tab 内容顶部，沿用 Kanban 筛选栏的控件顺序、标签、样式和键盘交互。

Kanban 与任务流转图分别维护以下状态：

- 搜索文本
- 已选择的主任务 ID
- 工单类型
- 执行者

切换 Tab 时保留两个视图各自的状态。主任务目录或执行者列表刷新后，如果当前选择仍然有效则继续保留；若具体执行者已经不存在，则回退为“所有 Agent”。

筛选结果为空时，任务流转图显示明确的空状态，不展示不完整的项目泳道。

## 组件与数据流

筛选栏抽为两个视图共享的展示组件。组件只接收筛选值、选项和变更回调，不拥有业务状态，也不负责筛选数据。

`ApiWorkspace` 分别保存 Kanban 和任务流转图的筛选状态，并通过同一个纯筛选规则计算两个可见 WorkItem 集合：

1. 主任务筛选先限定项目范围。
2. 类型和执行者筛选与项目范围取交集。
3. 搜索词最后在剩余 WorkItem 中匹配。
4. Kanban 使用自己的结果渲染卡片。
5. 任务流转图使用自己的结果渲染 Root、Milestone 和 Task 节点。

任务流转图的项目泳道由可见子任务重新生成。依赖线仅在依赖双方节点都可见时绘制，因此不会出现指向已隐藏节点的悬空连线。节点仍使用原始 WorkItem ID 打开详情。

## 状态与兼容性

筛选状态仅存在于当前页面会话，不新增本地持久化。项目数据刷新和任务详情编辑继续使用现有数据源。

现有 Kanban 行为与默认值保持不变。首次打开任务流转图时，四个筛选条件均为“全部”或空搜索，因此默认展示与当前版本相同的完整流转图。

## 测试

前端测试覆盖：

- Kanban 与任务流转图的筛选条件相互独立，并能在 Tab 切换后恢复。
- 任务流转图的搜索、主任务、类型和执行者筛选生效。
- 多个条件按交集组合。
- 被过滤掉的子任务不再生成节点；依赖一端不可见时不绘制对应依赖线。
- 空结果显示空状态。
- 默认状态和节点点击打开详情的既有行为不回归。
